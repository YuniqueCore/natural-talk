# 反面教材案例库：技术踩坑/过程文写作

来源：2026-09 实时视频换装教程文，同一题材连写四版、被退三次，第四版后由用户亲手改定（v5 终稿）。本文同时收录用户的改法——它们是所有条目的最高基准：判别标准从"像不像人写的"最终升级为"是不是真的"。
收录说明：条目标注【命中轮次】（v1 初稿 / v2 风格重写 / v3 平实重写 / v4 细节轮）。同类病灶重复出现的做了累计，累计次数越高说明越是模型的默认习惯，越要警惕。
v1.1 扩充：第九节新增英文 AI 腔（收敛自 humzakt/ai-writing-markers、MikkoParkkola/anti-ai-tell、tbhb/vale-ai-tells 三个带实证来源的词库，已并入 anti-slop-kit）；正面基准补好文检测校准数据与诚实写法摘录。
用户三轮反馈的原话关键词：**"AI slop"、"站在上位进行描述的描述语法"、"太详细了"、"小细节完全不重要"、"用词不平民，词藻组合有问题"、"不要有这样站在上位进行描述的描述语法"、"简单直白的记录文档"**；验收标准："小白踩坑式输出，只是文本内容风格要求思维逻辑，前后关联"、"文本可以多且长，不精良，不精炼，但一定要有思维，有人味"。

写技术过程文、踩坑记录、教程文之前先通读本文。每条格式：病灶原文（退稿里的真实句子）→ 为什么糟 → 实际改法。

## 一、上位者旁白（最高频病灶，三轮全部命中）

作者跳出当事人视角，站在讲解者的高度对读者说话、对事件下评语。这是 AI 过程文最重口的味。

| 病灶原文 | 为什么糟 | 改法 |
|---|---|---|
| "原因很简单：视频模型牵扯的东西太多" | "原因很简单"是讲台腔，判断替读者做了 | 直接给原因："视频模型变量太多，卡住了分不清是模型问题还是我工程没搭好" |
| "然后我做了一个取巧的设计" | 自我评价词。"取巧"是作者给自己发弹幕 | 删评价，直接写做了什么："视频第一帧用 FASHN 换装，后面的帧用光流搬运" |
| "值得多说两句""值得展开讲" | 导播腔，宣布接下来要精彩 | 删掉，直接讲 |
| "这里有个明显不合理的点""有个认知转折值得说" | 旁白提示"此处应有思考"，思考本身却没写 | 把思考过程平铺出来，不预告 |
| "这在视频生成里是快得离谱的存在" | 仰视式感叹，读者自会判断 | 留事实："去噪压到 4 步" |

**自查**：全文搜"原因很简单 / 值得 / 显然 / 当然 / 很自然 / 取巧 / 聪明的做法"，每一处问：这句是在做事，还是在点评做事？

## 二、事后点评与经验总结腔

写完一段事实，非要跳出来宣布"这段教会了我什么"。第一次经历时并不知道教训，教训是写文章时补的，一补就假。

| 病灶原文 | 为什么糟 | 改法 |
|---|---|---|
| "这件事给我的教训是：同一个报错可能有多种改法能让它消失，但只有跟模型真实结构一致的那种改法是对的" | 格言式收束，把排查过程压缩成人生道理 | 删。前文"先试了让下游兼容 22 帧，崩得更早……最后两个报错一起消失"已经把事说完了 |
| "从那以后我养成了一个习惯：打补丁之前，先打印运行时加载路径" | 习惯溯源无法验证，且是典型的"经验+1"模板 | 删，或降级为事实："之后再排查时会先打印运行时实际加载的文件路径"（仅当确实这么做） |
| "这一段的心得就一句：模型效果不好，先别急着调参数" | "就一句"之后必然跟三句 | 删整句。结论让表格和事实自己站住 |
| "它后来决定了整个项目的走向""这半天没白花" | 事后视角的预告与追认，写第一版时并不知道这些 | 删。前后关联让读者从后文自己看到 |
| "先跑通，再跑好，顺序不能反""两条战线同时开打，大概率两头都输" | 口诀化排比，是给读者的忠告不是给自己过程的记录 | 删 |
| "这版能跑，3 秒的视频 5 秒出片……但问题也清楚：……"【v4】 | 评价式过场：先替成果打分，再宣布"问题也清楚"，都是卷面话 | "跑起来了，3 秒的视频 5 秒出片……多试了几段就露馅了：动作一大衣服开始糊" |
| "类似的坑前前后后一共九个"【v4】 | 精确计数癖。正常人一边修坑不会一边数数，精确数字反而假 | "大大小小的坑改了十来处，具体多少没认真数，改到后面已经懒得记了" |
| "一天时间，能跑了。"【v4，用户改】 | 报喜藏忧：只说跑通，不提效果差。AI 的默认倾向是把成果包装到展示的那一刻 | 用户定稿："一天时间，能跑了，虽然效果着实不行，但依旧把过程记下来" |
| "定版输出（49 帧里抽了 5 帧）："【v4，用户改】 | 同病：贴成果图前不交代真实水平 | 用户定稿："……效果看起来很滑稽，但也算完成了持续的换装" |
| "它只能算验证了工程链路，离'实时换装'还差一个真正的视频模型" | 给自己的工作打分定位，旁白视角 | 删评价，留事实："动作大了衣服会糊，时间长了误差累积画面越来越脏" |

**自查**：搜"教训 / 心得 / 学到 / 这件事让我 / 从那以后 / 后来证明 / 决定了整个"，逐处判断：不写这句，事实链断吗？不断就删。

## 三、金句癖

把结论锻造成对仗短句，看起来漂亮，读起来是AI最重的味。

| 病灶原文 | 病因 | 改法 |
|---|---|---|
| "眼睛会骗人，均值不会" | 对仗金句 | 删。前一句"人眼看两遍的结论都不一样"已经成立 |
| "别怪模型菜，先检查它的口粮" | 押韵卖萌 | 删 |
| "条件质量的差距，比任何调参都大" | 夸断。"任何"无法证 | 留数字对照："7.42 对 4.63" |
| "补丁要打在数据流真正经过的那一行" | 提炼成原则后失去了具体性 | 留事实："wan_base 是符号链接，指向 CausVid 的老代码，我改的文件不是运行时加载的文件" |
| "这类换装模型是个听话的厨师，你给它什么食材，它出什么菜" | 加粗居中的"核心认知"排版腔 | 降级为普通陈述句，或删 |
| "谁闲着谁干活""流水线化真正消除的不是耗时，而是等待" | 后者是翻案腔+金句双杀 | "省下的十几秒编码挪到了用户挑衣服的时间里" |

**自查**：搜自己的成稿，凡是你会想加粗、想让人摘抄的句子，删掉重写成平句。想被摘抄的冲动本身就是病灶。

## 四、戏剧化表演叙述

把排查过程写成悬念片。第一次经历时确实懵，但"懵"不需要演。

| 病灶原文 | 为什么糟 | 改法 |
|---|---|---|
| "当时看到这个报错是完全懵的。但数字不会骗人，我把它拆开算了一遍" | 表演困惑再表演顿悟 | "当时没头绪。拆开算：21 是 latent 帧数……" |
| "我点开视频，一片深灰色的噪点。说实话这个结果让我愣了几秒" | "说实话""愣了几秒"是表演性真实 | "点开视频，深灰色噪点在动，没有人物。测试用的条件视频本来就是灰色占位的" |
| "对，你没看错。你按它的 README 跑，第一行推理就会崩。而且崩完一个还有一个" | 跟读者咬耳朵，制造惊讶 | "官方仓库的代码和发布的模型权重对不上，第一处推理就崩，前后一共九处" |
| "然后就被教育了。""这就是那次著名的失败。" | 自我戏剧化 | "跑出来是一件白色的、缓慢蠕动的团。模型把换装区域还原成了白 T 恤" |
| "又踩了一轮坑""这次偷懒的后果马上就来了"【v2、v3 各一次，累计 3 种变体】 | 预告式过渡：宣布"接下来要出事了"而不是让事自己发生 | 删过渡，直接写结果："条件当时图省事……跑出来是一团白色的东西" |
| "前几天在小红书群里聊天……最后有人冒出来一句：这些都不算什么……"【v4，用户改】 | 编造场景和对话。真实情况是看到有人发布需求，不存在"冒出来一句"的群聊戏剧再现 | 用户定稿："看到有人对外发布 AI 识别衣服、自动搭配衣橱，以及……实时跟踪换装渲染的需求" |
| "大家都说这东西肯定有人做"【v4，用户改】 | 虚构群体反应烘托氛围 | 用户定稿："这东西不用想都知道肯定有人做"——自己的判断，不借别人的嘴 |

## 五、详略失当

小问题写两大段，真正罕见的反而一笔带过。

病灶实例（退稿原样）：交叉注意力函数签名对不上（常规兼容问题）写了两大段，包括包装函数怎么写的、查了几遍；而 Triton 编译器在 AMD 上崩溃（罕见、值得记录）反而和它平铺直叙混在一起。

改法：
- 常规问题一句话："交叉注意力的函数签名对不上，查了半天发现 `wan_base` 是符号链接指向老仓库，改调用点对齐老签名。"
- 罕见问题才给位置：报错原文 + 定位过程 + 修复代码。
- 判据：**别的开发者遇到时，搜报错能搜到解决办法吗？写的内容比搜索结果多出什么了吗？** 搜得到的不写或一笔带过。

## 六、该贴代码不贴，该对比不对比

| 病灶原文 | 问题 | 改法 |
|---|---|---|
| "光流就是算出相邻两帧之间每个像素移动的方向和距离，OpenCV 里一行函数的事" | 说"一行函数"却不给这一行 | 贴出来：`cv2.calcOpticalFlowFarneback(...)` + `cv2.remap(...)` 完整片段 |
| "修法是绕开编译，换成普通注意力函数" | 只有文字没有代码 | 贴替换前后的代码对比 |
| "改成衣服 token 不进序列、只走交叉注意力" | 改动没有代码形态 | 贴删掉的行、改后的行 |

涉及代码改动的地方，代码对比比文字描述高效十倍。文字只负责代码看不出来的部分：为什么这么改、当时怎么定位的。

## 七、模板化结构

三版退稿共享的 AI 结构指纹：

- 「阅读目录」引用块 + 编号小标题（一、二、三）——教程腔标配
- 每节固定节奏：设问开场 → 白话解释 → 代码 → 小结，节节如此
- 每节末尾一句加粗"结论"
- "写在最后"三段式升华（三句话认识 / 三个认识是事先没想到的）
- 对照图必配一句"这一步的改进是 38%，让感觉变成了证据"

改法：小标题用朴素短语（"调研""输出是一片灰色""缓存"），无编号；段落长短自然，有的节只有两三句；结论写在事实旁边即可，不加粗不单独成段；收尾一段说完最后一件事即停。

## 八、词藻与句法杂项

| 病灶 | 改法 |
|---|---|
| "把 整条链路——网页摄像头、传输、逐帧处理、输出——先搭起来" | 破折号插说改括号或拆句 |
| "一件白色的、模糊的、缓慢蠕动的团状物" | 三连"的"定语堆叠，留一个："一件缓慢蠕动的白色团"或直接"模型把区域还原成了白 T 恤" |
| "喂进第一个任务""安安静静给你错的结果""悄悄漂一个坐标" | 拟人小尾巴，动词自己站住 |
| "以编译困难闻名的框架""快得离谱的存在" | 定语评价删掉，事实自证 |
| "毒打""被打回来""口粮" | 口水俏皮话，一次可以，连用成腻 |
| "左边那种红身子紫袖子黑肩膀的碎裂，就是模型在错误条件下的挣扎" | "挣扎"拟人化形容 + 戏剧化命名（红身子紫袖子黑肩膀） | "左边是近似条件下的输出，衣服碎成多块颜色" |
| "老老实实把条件链补齐""我又偷懒了"【v4】 | 自我性格表演副词：给自己此刻的态度加戏 | "之后把条件链按官方要求补齐""条件这块当时图省事" |
| "喂进去第一个任务"【v4】 | 动词不得体（把模型当牲口喂） | "跑第一个任务就报错了" |
| "光流搬不动真正的换装"【v4】 | 拟人 + 宣判腔 | "光流只能把像素搬来搬去，衣服的样子不会跟着动作变，真要换装还是得靠模型重新生成" |
| 评测指标写成三连排比（"没乱画、真换了、换得稳"）【v4】 | 工整对仗是 AI 指纹；指标解释应该是思路不是口号 | 拆成一段叙述："换装不能动背景和脸，所以先算……换装又必须真的发生，所以……" |
| "只能在别人家网页上换别人家的模特"【v4，用户改】 | 戏谑代准确：顺口溜式调侃丢了产品形态的事实 | 用户定稿："只能在别人家网页上调用 API 直接得到结果" |
| "这就是那次著名的失败" | 不著名。自我引用式夸张 |

## 九、英文技术文档的 AI 腔（v1.1 扩充）

来源：humzakt/ai-writing-markers（CC0 数据集）、MikkoParkkola/anti-ai-tell（带实证标注）、tbhb/vale-ai-tells（Vale 规则库）的保守子集，已并入 anti-slop-kit 词库。中英混排的 README、博客、发布说明都会踩。

| 病灶 | 为什么糟 | 改法 |
|---|---|---|
| "X serves as a Y" / "stands as a" / "marks a new era" / "represents a shift" | 系词回避：LLM 比人类多 10% 概率不用 is/are/has（Geng & Trotta） | 还原系词："X is a Y" / "X has" |
| "It matters." "This works." "And it shows." | mic-drop 短句：在平静的技术讨论里拍惊堂木 | 把论点并进前后句 |
| "The catch? Nobody tells you..." "The result? Chaos." | 自问自答当鼓点 | "The catch is that nobody tells you..."，或直接陈述 |
| "The tradeoff:" "The bottom line:" "The kicker:" | 标签加冒号，标签本身零信息 | 写完整句；标签删掉 |
| "This matters because..." "The key here is..." "**Key takeaway:**" | 元评论：宣布"此处重要"而非让内容自己重要 | 删宣告，留论点 |
| "paves the way for" "along the way" "the road ahead" "journey" | 旅程隐喻滥用 | "enabled" "made possible"，或写实际后果 |
| "left an indelible mark" "setting the stage for" "the transformative power of" "offers a glimpse into" | 万能填空短语，换个主语照样通顺=没信息 | 写具体改变了什么、给谁看 |
| "commendable" "garnered" "unveiled" "invaluable" "versatile" "skyrocketing" "aptly" "lucidly" "comprehensively" | 实证超额词（Liang 2024：commendable 在 ICLR 审稿里涨 9.8 倍） | 用平词："good" "won" "released" "helpful"，或给数字 |
| "Based on the information provided, ..." | 聊天残留：把对话当任务复述 | 直接回答 |
| "I hope this email finds you well" | 邮件套话（ human 也用，但 AI 从不省略） | 删，或换成一句真话 |
| "Think of it as a Swiss Army knife for X" | 现成比喻模板 | 机制型比喻保留（"缓存像收发室的小黑板"），装饰型删 |

**注意**：这些是候选信号不是判决。"robust" 在工程语境、"ecosystem" 在生物语境受保护；人类赶稿时也会写 "The catch?"——孤立一次不构成证据，成簇才值得改。

## 十、正面基准

### 来自用户指定的"好文"（飞书收藏，博客园系）

- 《开发架构》：整个项目按"基础版 → S3 同步版 → 会员版 → CMS 版"演进，每版由一个真实需求逼出来。过程文就该这么组织。
- 《生产者/消费者模式》：寄信的类比从解耦、并发、忙闲不均一路用到颗粒度，一个类比贯穿全篇，不换喻体。
- 《多线程&线程池》：同一个例子重写三遍（Thread → ThreadPool → Task），演进式教学；口语过渡（"诶，相信现在你明白了"）。
- 《算法》：开篇坦白"答案不具代表性也并非正确答案，仅仅分享"，收尾"欢迎各位道友给出更好的答案"。
- 口语连接词随便用：好了、这不、诶、说来也怪；段落长短天然不齐（有的段一句，有的段一大坨）。

### 好文的检测器校准数据（v1.1）

用 anti-slop-kit 词库跑真实好文，结果说明"上限语义"为什么重要：

- 《手撸一套纯粹的CQRS实现》：962 单位，1 处命中（"本文旨在"），评分 1.0/千单位，band=light。开头交代文章意图是体裁常规，复核后放行。
- 《多线程&线程池》：2544 单位，1 处命中（"随着c#的不断发展"），评分 0.8，band=light。这句确实是壳，但全文口语气重、例子真实，孤立一处不值得动。
- 结论：真人好文不是 0 命中，是**低密度 + 每处命中都能给出放行理由**。把真人文本刷到 0 分的清理本身就是过度清理。

### 好文里的诚实写法（值得抄的）

- 《CQRS》：代码中间突然插一句斜体自嘲——"*我不知道这里直接使用DTO对象来初始化是否合理，我先这样来实现*"。拿不准就承认拿不准，读者反而信。
- 《CQRS》结尾："如果代码中有错误或不合适的地方，请在评论中指出，谢谢支持。"收尾是行动请求，不是升华。
- 《多线程》：同步原语讲完主动交代边界——"线程池也有劣势，譬如它只是个可复用线程队列……Thread 就不一样"。报限制不藏拙，和 v5 用户定稿的"虽然效果着实不行"同一件事。

### 用户定稿（v5）——最高基准

第四版写完后用户亲手改了两处开场、一处成果展示，外加若干用词。所有改动指向同一件事：**把编的场景换回事实，把藏住的丑话放到前面**。"虽然效果着实不行，但依旧把过程记下来"是全篇最有说服力的一句——它不损害分享的价值，反而让后面所有内容都可信。

### 第四版被认可的改法（对照上面病灶看）

- "跑起来了，3 秒的视频 5 秒出片……多试了几段就露馅了"：结果和发现写成连续动作，不打分。
- "大大小小的坑改了十来处，具体多少没认真数，改到后面已经懒得记了"：模糊计数才是真记过账的人。
- "这一段的定位我是让 AI agent 帮着查的，它翻到……它给的修法是……"：诚实记录工具参与，注明谁找到的。
- 素材图、条件图直接贴进文里，让读者看到输入长什么样。

- 开场从真实缘起直接进："前几天在小红书群里聊天……就想自己做一个，前后花了一个多星期，这篇是过程记录。"
- 每个决定带因果，前后呼应靠事实回收：灰色输出呼应灰色占位、镜像坑呼应后面的参考图实验。
- 报错原文照抄，推算过程给算式（44616 − 42588 = 2028），不给感叹。
- 代码改动给对比片段；小问题一句话，罕见问题给全文。
- 数字给三件套（没乱画 / 真换了 / 换得稳）但不提炼成人生道理。
- 收尾是文件清单加致谢，不是三句话认识。

## 十一、发稿前自查清单

1. 搜"原因很简单 / 值得 / 其实这件事 / 教训 / 心得 / 从那以后 / 后来证明"——上位者旁白清零。
2. 搜对仗短句和想被加粗的句子——金句清零，改平句。
3. 搜"说实话 / 愣了几秒 / 你没看错 / 完全懵"——表演性真实清零。
4. 每个小问题：是否一句话带过？每个展开的问题：比搜索结果多出东西了吗？
5. 涉及代码改动：有代码对比吗？
6. 删掉"阅读目录"和编号标题（除非平台明确需要）。
7. 通读一遍：像开发者在工位上跟同事复述这几天干了什么，还是像一个人在台上讲《我从 XX 学到的十件事》？后者重写。
8. 场景、对话、群体反应有真实出处吗？没发生过的对话、"大家都说"式的群体声音，删掉换成事实。
9. 每处成果展示：真实水平交代了吗？"能跑了"后面应该跟"虽然效果着实不行"——藏拙不是谦虚问题，是可信度问题。
10. 跑 `anti-slop-kit/scripts/slop_check.py`：light 以下逐条复核给放行理由即可；heavy 说明成簇病灶没清完。真人好文通常是 light——目标是低密度，不是 0 分。
11. 英文段落加查：系词回避（serves as / stands as / marks a → is / has）、mic-drop 短句、标签冒号、"The catch?" 自问自答、旅程隐喻（见第九节）。
12. **事实逐条核对**：名字、数字、法条、奖项归属、机构名。编造是唯一不可原谅的 slop（见第十二节）——风格工具抓不住它，只有对照真实来源能抓住。

## 十二、编造与对冲（v1.3，来自偏好对语料的实证）

anti-slop-kit dataset/ 的 45 对人机对照语料里，这一类是机器检测完全测不到、
只能靠核对事实才能抓住的重灾区。风格上它们甚至"读着挺顺"。

| 病灶原文（HC3 语料实录） | 为什么糟 | 好侧怎么写 |
|---|---|---|
| "图灵奖……由英国计算机协会（British Computer Society）颁发" | 编造事实：图灵奖是 ACM 颁发的。句式通顺、细节齐全，假得更可信 | 好侧给可核对细节：1966 年设立、截至 2021 年 74 名得主、高校人数分布 |
| "工伤按照严重程度分为甲级、乙级、丙级和丁级四级" | 编造法条：中国伤残鉴定是 1-10 级，不存在甲乙丙丁级。编完还补一句"建议咨询律师"兜底 | 好侧给程序与时限：30 天工伤认定、伤残鉴定、赔偿科目清单 |
| "很抱歉，我无法为您提供具体的法律建议，因为我是一个计算机程序" | 免责声明开场：先把"我不能"说足，再给通篇正确的废话 | 好侧（执业律师）直接给步骤：起诉法院、调取银行资料、申请冻结 |
| "在某些地方可能不受法律保护……在其他地方可能受到保护……总之，应当根据当地的法律了解其相关规定" | 对冲到底结论为空：每句都是「可能」，「总之」之后让读者自己去查 | 好侧分三种情况，每种给确定性处理规则 |
| "转账的时间受到许多因素的影响，包括……（同一句原样重复两遍）……因此，无法确定" | 原句复述凑字：把排比铺满、结论留白；另一条语料把同一句话重复两次 | 好侧一句话：8 点到 15 点两小时内到账 |

**自查**：成稿里每一个专有名词、数字、归属关系，问一句"我从哪知道的？"
答不上来的删掉或查证。对抗编造不靠风格，靠核对。

## 十三、正面基准：真实问答里的人味（v1.3，HC3 语料）

真实的人类回答长什么样——同一批语料里的人侧样本：

- **防骗经验**（问急用钱借不到）：「如果先让你交费用，八成都是骗人的，我是济南的」——地方经验、
  口语判断、顺带自我介绍。没有一条列表。
- **手机干扰**（问音箱为何在短信前出声）：「"喂手机你在吗？""在的，有条短信，你在哪？"」——
  用一段拟人对话讲完 GSM 建连与功率爬升，比教科书准确又好记。
- **诊疗计划**（问胸痛）：先定位（氯气刺激性支气管炎）、再给药（抗组胺+消炎）、给复诊条件
  （5 天不好再拍片）——每步可执行，无一句"建议咨询医生"的兜底。
- **法律程序**（问存款被朋友的卡扣住）：编号列步骤、每步一个动作（起诉、调资料、申请冻结），
  反问句收尾（"何况卡还在你们手中？"）。

这些回答的共同点：**判断具体、路径可执行、允许口语**。对照第十二节的编造样本，
可以看出"好回答"从来不是把正确废话写整齐。
